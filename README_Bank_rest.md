## Описание

Система управления банковскими картами — это REST API приложение, разработанное для создания, управления и просмотра банковских карт, а также выполнения переводов между ними. Проект реализован с использованием Spring Boot и обеспечивает ролевой доступ (ADMIN и USER) с аутентификацией через JWT. Номера карт шифруются с помощью PostgreSQL `pgcrypto`, а баланс хранится с точностью до двух знаков после запятой.

## Функциональность

### Атрибуты карты
- **Номер карты**: Хранится в зашифрованном виде (PostgreSQL `pgcrypto`), отображается в маскированном формате (`**** **** **** 1234`).
- **Владелец**: Имя и фамилия владельца карты а также ссылка на сущность пользователя владельца карты.
- **Срок действия**: Дата истечения срока действия.
- **Статус**: `ACTIVE` (активна), `BLOCKED` (заблокирована), `EXPIRED` (истёк срок).
- **Баланс**: Числовое значение с двумя знаками после запятой (например, `100.50`).
- **Запрос на блокировку от пользователя**: true или false.

### Возможности по ролям
#### Администратор (роль `ADMIN`)
- Создание, блокировка, активация и удаление карт.
- Управление пользователями (только просмотр).
- Просмотр всех карт в системе с поддержкой поиска, пагинации и фильтрации по параметрам.

1 пользователь ADMIN добавлен с помощью миграции БД для тестирования с помощью Postman. ID: "1", username: "Admin", password: "Admin"

#### Пользователь (роль `USER`)
- Просмотр своих карт с поддержкой поиска, пагинации и фильтрации по параметрам.
- Запрос на блокировку карты.
- Переводы между своими картами.
- Просмотр баланса.

## API Эндпоинты

| Метод | Эндпоинт | Роль | Описание |
|-------|----------|------|----------|
|Регистрация и аутентификация |
| **POST** | `/api/auth/login` | Все | Аутентификация и получение JWT токена |
| **POST** | `/api/auth/signup` | USER | Регистрация нового пользователя |
| Управление картами |
| **POST** | `/api/cards` | ADMIN | Создание новой карты |
| **GET** | `/api/cards/{id}` | Все | ПОиск карты по ID (ADMIN - любая карта в системе, USER - только свои карты) |
| **PUT** | `/api/cards/{id}/block` | Все | Блокировка карты (ADMIN) или запрос на блокировку (USER) |
| **PUT** | `/api/cards/{id}/activate` | ADMIN | Активация карты |
| **DELETE** | `/api/cards/{id}` | ADMIN | Удаление карты |
| **GET** | `/api/cards` | Все | Просмотр всех карт по заданным параметрам в Params (ADMIN - все карты, USER - только собственные) |
| **GET** | `/api/cards/all` | Все | Просмотр своих карт для USER. Просмотр всех карт в системе для ADMIN |
| **POST** | `/api/transfers` | USER | Перевод между своими картами |
| Управление пользователями |
| **GET** | `api/users/{id}` | ADMIN | Поиск пользователя по ID |
| **GET** | `api/users` | ADMIN | Просмотр всех пользователей |

## Структура запросов и ответов

Более подробная документация содержится в ./docs/openapi.yaml

### Аутентификация
- **POST /api/auth/login**
    - **Запрос**:
      ```json
      {
        "username": "Admin",
        "password": "Admin"
      }
      ```
    - **Ответ (200 OK)**:
      ```json
      {
        "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
      }
      ```
    - **Ошибки**:
        - `401 Unauthorized`: Неверные учетные данные.

### Создание карты (ADMIN)
- **POST /api/cards**
    - **Заголовки**: `Authorization: Bearer <jwt_token>`
    - **Запрос**:
      ```json
      {
        "cardNumber": "1234 5678 9098 7654",
        "expiryDate": "01/29",
        "userId": 2
      }
      ```
    - **Ответ (201 Created)**:
      ```json
      {
        "id": 1,
        "number": "**** **** **** 7654",
        "owner": "Name Surname",
        "expiryDate": "01/29",
        "balance": "0.00",
        "status": "ACTIVE",
        "userId": 2
      }
      ```
    - **Ошибки**:
        - `400 Bad Request`: Неверный формат номера карты или даты.
        - `403 Forbidden`: Недостаточно прав (не ADMIN).
        - `404 Not Found`: Пользователь не найден.

### Просмотр своих карт (USER)
- **GET /api/cards/my?page=0&size=10&search=1234**
    - **Заголовки**: `Authorization: Bearer <jwt_token>`
    - **Ответ (200 OK)**:
      ```json
      {
        "content": [
          {
            "id": 1,
            "number": "**** **** **** 7654",
            "owner": "Name Surname",
            "expiryDate": "01/29",
            "balance": "100.50",
            "status": "ACTIVE",
            "userId": 2
  
          }
        ],
        "pageable": {
          "pageNumber": 0,
          "pageSize": 10
        },
        "totalElements": 1
      }
      ```

### Перевод между картами (USER)
- **POST /api/transfers**
    - **Заголовки**: `Authorization: Bearer <jwt_token>`
    - **Запрос**:
      ```json
      {
        "fromCardId": 1,
        "toCardId": 2,
        "amount": 50.00
      }
      ```
    - **Ответ (200 OK)**:
      ```json
      {
        "transferId": 1,
        "status": "SUCCESS",
        "fromCardId": 1,
        "toCardId": 2,
        "amount": "50.00",
        "timestamp": "2025-08-29T14:00:00"
      }
      ```
    - **Ошибки**:
        - `400 Bad Request`: Недостаточно средств или неверные ID карт.
        - `403 Forbidden`: Карты принадлежат другому пользователю.

## Безопасность

- **Шифрование номеров карт**: Номера карт хранятся в зашифрованном виде в столбце `number` (тип `bytea`) с использованием `pgp_sym_encrypt`/`pgp_sym_decrypt` из PostgreSQL `pgcrypto`. Ключ шифрования задаётся в `application.yml` (`encrypt.key`).
- **Маскирование**: Номер карты отображается в формате `**** **** **** 1234`.
- **Ролевой доступ**: Spring Security с JWT ограничивает доступ к эндпоинтам в зависимости от роли (`ADMIN` или `USER`).
- **Валидация**: Входные данные проверяются (например, формат номера карты: `1234 5678 9098 7654`).
- **Ошибки**: Подробные сообщения об ошибках возвращаются в ответах API (например, `400`, `403`, `404`).
